# 月度事件压缩规则

月度压缩的目标不是生成月报，而是把完整原始 Input 变成可信、低重复、月份正确的 AI 上下文。原文继续保留在 `03_input/`；压缩结果只进入 `_dist`。

## 不可违反

- 只写原始来源能够支持的事实、判断和不确定性，不补造因果、人物、行动、结果或意义。
- 只保留目标月发生的事件。来源横跨月份时，删除月外事件；无法判断日期时省略并说明原因。
- 按事件压缩，不按文件机械截断。一个事件由相同人物、问题、行动和反馈组成；同一来源可拆成多个事件，多份来源也可合并为一个持续事件。
- 先删除重复、采集元数据、口头填充、目录、模板和无变化快照，再压缩正文。
- 保留时间、人物、真实行动、现实反馈、关键判断、反例、失败、限制和下一步。漂亮表达不能替代事实。
- 只要内容会改变认知、决策或行动，就完整保留这个独立信息单元；不得因为来源长、总字数多或目标压缩率而删除。
- 必须保留用户的独立判断、判断变化与反转、外部真实反馈、不可替代的限定与风险、原句和隐喻、未闭环矛盾。长度不是重要性指标。
- 月记是用户月度自我反馈，保持原文，不与周材料做语义去重。

## 重要性与体积

重要性决定保留顺序和组织位置，不决定固定字数：

| 级别 | 判断标准 | 处理方式 |
| --- | --- | --- |
| `core` | 改变方向；独立判断；有真实行动或外部反馈；出现反转、限制或重要未闭环问题 | 保留全部独立核心信息；内容多时拆成多个事件，不截断 |
| `supporting` | 有具体问题、行动、判断或结果，能支撑月度主线 | 结构化压缩，保留证据、限定和结果 |
| `minor` | 单次、低影响、尚无反馈，但仍值得留下的信号 | 压成短列表，或有依据地省略 |
| 省略 | 空内容、技术元数据、月外事件、无变化重复、无法验证 | 0 字，并写明原因 |

不使用固定压缩倍率，也不设置迫使核心内容丢失的单事件上限。最终只受 Process Pack 100 KB 总边界约束；超限时优先继续压缩微信读书、Builder 流水、普通 Coach 过程和研究背景，不得裁掉核心判断。

## 来源处理

- `ai.md`：先验证为真实周回顾，提示词、模板和自动缺口说明必须排除。每周单独生成一个 `core` 事件，完整保留核心洞察、重要问题与阶段答案、判断变化、行动反馈、限定、反例、原句和未闭环问题；只删除模板、重复背景和同义重复。逐周事件之后才可增加 `source: ai-synthesis` 的跨周演化事件，不设置固定压缩倍率。
- `research.md` / 播客 / 访谈：先判断包含几个事件并分别评级。保留命题、关键论证、分歧、例子、限制与行动含义；删除寒暄、复述、口误和逐句展开，逐字稿不得全文进入 Process Pack。
- `weread.md`：保留各周有效阅读统计、月末进度、当月新增且去重后的个人划线与想法。相同划线只留一次；没有划线、想法或有效时长的周最多形成一个 `minor` 事件，也可以省略。
- `build.md` / `build-bot.md`：按项目或真实变化合并，保留关键决策、实际结果、失败、未验证状态和下一步；删除 commit、文件与日志流水、重复治理描述。
- `coach.md`：按服务对象、问题或项目事件化。保留真实问题、关键干预、观察到的反馈、判断变化、未闭环问题和下一步；压缩字段堆叠、重复背景与常规过程。包含真实外部反馈的核心案例不得被普通过程一起压掉。
- `monthly-journal`、`weekly`、`daily`、`flomo`、`health`、`voice`、`calendar`、`time` 默认只做确定性清洗、日期过滤和去重，不做语义压缩。Flomo 保留每条不同的个人判断；日历与时间材料删除系统元数据但保留实际时间、事项和时长。
- Weekly Output 只读取系统确认的标题 10「全文核心重点纪要」和标题 11「芒格之魂的洞察」，按周近乎原文保留；空项和 `todo` 跳过，不读取其它周报正文代替原始 Input。
- 对未列入固定来源策略的新类型，10 KB 按“目标月内同一类型的全部材料合计”计算，不按单文件计算。超过 10 KB 时由 Codex 做价值审查；10 KB 只是触发审查线，不是机械上限。
- 高价值、高信噪比、几乎没有冗余的新类型可以保留原文；中低价值、跨周重复、过程展开过多的部分应跨文件合并为事件压缩。
- `daily`、`flomo` 超过 10 KB 时仍只做确定性合并、去重和分段组织，不得因体积直接删除不同的个人判断、自我观察、行动或反馈。
- 超阈值类型中的单份高质量材料仍可使用 `passthroughs` 保留，但其余中低价值或重复材料必须压缩；所有决定均受 100 KB 总预算约束。

## 执行步骤

1. 读取 `_dist/monthly/YYYY-MM/compression-requests.json`。
2. 按请求中的路径读取每份当前原文，核对 SHA-256；不要使用旧摘要替代。
3. 先按 `source` 类型汇总月度总量；超过 10 KB 的类型整体审查。再列事件、合并同类型跨周重复，最后评级和压缩。先做事实清单，再写压缩正文。
4. 所有压缩事件必须分段分点。禁止把多个判断平铺成一个长段落；普通事件至少使用两个列表项，AI 周回顾至少使用三个四级小节。AI 周回顾推荐结构：

   ```markdown
   #### 本周主线
   - ...

   #### 核心洞察与判断
   - ...

   #### 重要问题与阶段答案
   - ...

   #### 判断变化、行动反馈与未闭环问题
   - ...

   #### 原句、隐喻、限定与反例
   - ...
   ```

5. 写入 `_dist/monthly/YYYY-MM/compressed-events.json`：

   ```json
   {
     "schemaVersion": 1,
     "month": "YYYY-MM",
     "events": [
       {
         "id": "E001",
         "title": "事件标题",
         "category": "action",
         "source": "research/podcast",
         "importance": "core",
         "dateRange": { "start": "YYYY-MM-DD", "end": "YYYY-MM-DD" },
         "sourcePaths": ["03_input/..."],
         "sourceHashes": { "03_input/...": "sha256" },
         "text": "压缩正文"
       }
     ],
     "passthroughs": [
       {
         "id": "P001",
         "title": "高价值原文标题",
         "sourcePath": "03_input/...",
         "sourceHash": "sha256",
         "dateRange": { "start": "YYYY-MM-DD", "end": "YYYY-MM-DD" },
         "reason": "为什么该来源高价值、高信噪比且不应压缩"
       }
     ],
     "omissions": [
       {
         "sourcePath": "03_input/...",
         "sourceHash": "sha256",
         "reason": "可核查的省略原因"
       }
     ]
   }
   ```

6. 运行 `npm run process:monthly -- --month YYYY-MM`。校验失败时修正压缩文件，不绕过哈希、日期、来源覆盖、AI 逐周核心事件、结构化正文或 100 KB 总预算。
7. 向用户报告每个类型及每个来源的原始字符数、压缩字符数、压缩率、事件数量、保留理由和省略原因。明确说明压缩由 Codex 完成，脚本只做确定性校验。

## 压缩前自检

- 如果删除这段，是否会改变对事件发生了什么的理解？
- 是否保留了行动和现实反馈，而不只剩观点？
- 是否把多个不同事件误合并成一条漂亮结论？
- 是否重复放大了跨周不变的同一内容？
- 是否存在来源中没有的因果、价值判断或确定性？
- 是否让单一长事件挤占了整个月的注意力？
- 是否错误地保留了字数最多的内容，而遗漏真正改变判断或行动的短内容？
- AI 周回顾是否逐周可见，并完整保留洞察、问题、反转、反馈、限定和未闭环事项？
- 压缩结果是否由小节与列表组成，而不是一整段平铺文字？
