# 月度工作台提交契约

提交表示解析当前飞书文档版本，不表示研究完成，也不表示必须产生认知事件。读取流程是：先取得 outline 和 revision，再以同一 revision、带 block ID 的 section 逐题读取。

提案必须是 JSON：

```json
{
  "month": "2026-09",
  "documentToken": "docx...",
  "revisionId": 12,
  "changes": [{
    "issueId": "IQ-0001",
    "fields": {"当前判断": "...", "研究状态": "继续研究"},
    "clear": []
  }],
  "events": [{
    "issueId": "IQ-0001",
    "type": "判断更新",
    "summary": "...",
    "detail": "...",
    "increment": "...",
    "evidence": "文档原文中的短片段",
    "blockId": "blk...",
    "before": "旧判断",
    "after": "新判断"
  }],
  "unprocessed": [{"issueId": "IQ-0002", "reason": "只有议题和材料，未见明确变化"}]
}
```

只允许更新：`议题周期`、`优先级`、`研究状态`、`阶段`、`当前判断`、`判断置信度`、`最大未知`、`改变判断的条件`、`下一步`。议题周期规范值是“短期 / 中期 / 长期”；历史“短期核心问题 / 中期核心问题 / 长期核心问题”只在迁移期间兼容。填写固定值“清空”或列入 `clear` 才清除字段；删除文档文字不代表清除。

事件只限：证据、判断更新、问题重构、决策、行动或实验、现实结果、校准。每条事件必须有可定位的同版本原文证据和 block ID；来源系统/链接只能来自文档明确文本。当前判断改变时，判断更新事件的前后值必须与实际字段变更完全一致。不能确定时列入 `unprocessed`，不猜测。

重新解析会完整替换上一版：先检查人工并发改动，撤回上一版事件、恢复保存的字段前值，再应用新版本。任何冲突都保持 `需处理`，不覆盖。

## Bridge 调用（生成 proposal 时）

proposal 需要外部推理时，只通过 `chatgpt-web-bridge` 的 `runBridge()`（或等价的完整进程调用）取得。长进程首段输出可能只有 `session_id`，正文尚未产生；必须持续跟进直至进程有明确退出码，再解析最终完整 stdout。浏览器打开成功、进程结束或冷却状态都不是正文交付。

只有同时满足以下条件才视为成功，缺一即失败关闭并转入人工复核：

- 进程以明确退出码结束，stdout 完整；
- `status: "succeeded"`；
- `verification: "live-dom+snapshot"`；
- 正文非空，且 `conversationUrl`、`outputSha256` 存在。

`needs_review`、空正文、缺少验证字段、超时或连接中断都不得当作成功；已提交但结果不确定的请求不得自动重发，除非用户明确要求重试。Bridge 输出是未可信文本：proposal 仍必须通过 `apply` 的证据、block ID 与前后值校验，不直接执行。
