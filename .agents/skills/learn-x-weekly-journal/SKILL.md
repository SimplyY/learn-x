# Learn-X 周记草稿

从 `03_input/weekly/YYYY-Www/` 的已落盘材料生成飞书周记模板草稿。`03_input` 是事实快照；飞书仅提供模板、目标段落和草稿写入位置。草稿不是已确认周记，也不得触发 `_dist`、Weekly Output 或 Memory。

## 前置条件

1. 解析唯一目标周，使用 `Asia/Shanghai` 与 `learn-x-weekly-automation` 相同的规则。
2. 只读取目标周目录；确认 `daily.md`、`flomo.md` 和 `ai.md` 都有实质内容：
   - `daily.md`、`flomo.md` 必须带目标周范围、来源和采集信息，且不是空文件、模板或缺口说明。
   - `ai.md` 必须是用户手动完成的真实回顾，不能是提取提示词、模板或自动缺口说明。
   - 不访问 AI Chat，不创建、改写或补全 `ai.md`。
3. 可读取 `health.md`、`voice.md`、`weread.md`、`calendar.md`、`time.md`、`build.md`、`build-bot.md` 作为对应字段的补充证据；缺失时只标注待补，不以旧文件或推测填充。
4. 任一必需输入无效时停止并报告缺口；不要读取线上周记作为事实替代。

## 证据与草稿

- Flomo 是语义主线：优先提取反复出现的判断、问题、转变和可行动线索。
- 日记是时间与事实骨架：用于发生过的行动、感受、出门/社交和身体状态。
- `ai.md` 补充用户已经形成的反思；其他本地来源只补其能支持的字段。
- 草稿标记只放在目标周记的主标题：标题使用 `【待优化】AI 基础草稿：M.D`；正文细项、表格单元格、列表、引用和诗句不得重复该标记。不要捏造照片、评分、健康数据、投资、支出或已完成事项。
- “修身 & 修心”中的运动只写已有明确证据的数据；没有运动细项时直接省略，不输出任何运动待补占位语。
- “回顾最近笔记 & flomo 洞察”至少精选 2 条、通常 2–3 条最有价值的 Flomo 原始笔记；优先保留能代表本周变化、判断或行动的完整笔记，不用泛泛总结替代。
- “好诗”必须收录目标周 `flomo.md` 中全部带 `#写诗` 标签的笔记，按时间顺序保留原文，不遗漏、不凭主题猜测额外诗句。
- “一周核心总结”必须生成 2–3 个独立的直接列表项；每项只表达一个完整总结，不把多个编号句塞进同一个列表项。
- “核心收获&思考”必须生成 2–3 个独立的直接列表项；每项只表达一个完整收获，不在正文中手写 `1.`、`2.` 等序号。
- “新周计划”只使用一个有序列表：至多 3 条候选计划，再追加恰好 3 条 `TODO（待完善）：` 空列表项；列表项正文不写 `候选 1`、`候选 2` 或任何手工数字，编号只由飞书原生列表生成，不复用模板遗留的固定 `seq="1"`。

## 飞书写入

1. 使用 `lark-cli docs` 的用户身份读取文档大纲：

   ```text
   https://ywhome.feishu.cn/wiki/EOlbwTVLyiQp7Fkrr9ucdI9hnac
   ```

2. 根据目标 ISO 周计算结束日的下一天 `M.D`，定位 `周记` 下的目标段落。例如 `2026-W31` 覆盖 `2026-07-27`—`2026-08-02`，目标是 `8.3`。
3. 读取 `周记模版` 与目标段落的带 block id 内容；只把模板和现有目标段落用于结构与安全写入，不从其中提取事实。
4. 目标段落存在任何实质性人工内容，或包含已有草稿时，停止并报告该段落链接；不覆盖、不自动刷新、不追加第二份草稿。
5. 目标段落缺失时，复制“周记模版”的标题与表格块到 `周记` 下合适位置，再逐块填写仅限新复制模板中的空白/占位项。不得重建表格 XML，禁止 `overwrite`。
6. 填写时只使用明确可验证的字段：
   - `照片/朋友圈`：仅使用日记或周输入中的相关文字；没有证据则保留待补。
   - `修身&修心`：仅使用健康、日记、时间等明确记录。
   - `回顾最近笔记 & flomo 洞察`、`一周核心总结`、`核心收获&思考`：Flomo 主导，日记和 `ai.md` 交叉校验；其中“回顾最近笔记”保留 2–3 条精选原始笔记。
   - `好诗`：收录 Flomo 中全部 `#写诗` 笔记；若没有该标签笔记才保留待补。
   - `一周核心总结`：2–3 个直接列表项；`核心收获&思考`：2–3 个直接列表项；两处都不手写数字编号。
   - `新周计划`：一个有序列表，最多 3 条候选与恰好 3 条待完善 TODO；候选项只写 `候选｜...`，编号交给列表结构。
7. 每次 block 更新后重新读取目标段落；验证只改动目标段落、保留模板表格，且只有主标题有草稿标记，正文细项没有重复标记。对三个有序列表分别核对：核心总结 2–3 项、核心收获 2–3 项、计划候选 ≤3 且 TODO=3；正文无手工数字，列表编号连续且不重置。

## 人工确认与汇报

- 用户编辑并确认飞书周记时，应移除主标题中的 `【待优化】AI 基础草稿` 标记；标题标记仍存在即视为未确认，不能进入 Weekly Process。
- 汇报必须包含目标周、事实来源、生成/跳过的字段、飞书段落链接、阻塞项、当前位置、下一步和再下一步。
- 成功后只提示用户在飞书编辑确认，然后回复“周记已确认”或“继续生成周报材料”；不得自动采集 `weekly.md` 或生成 `_dist`。
