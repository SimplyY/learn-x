# Memory 压缩规则

## 目标与边界

压缩只生成可人工审核的候选，不直接改写 `01_core/memory/`。候选放在 `04_output/_dist/memory-compression/YYYY-MM/`，候选正文只保留可读 Markdown；源路径、源 SHA-256、字符统计口径、预算和保护单元放在同目录隐藏的 `.memory-compression.json`，并完整显示在 comparison 报告中。脚本只做规划、哈希、结构和字符校验；语义压缩由 Codex 完成。

当前月、跨越当前月的周块、无法识别来源的条目默认保护。当前年使用季度文件；上一年度在新年度开始后才合并为一个年度文件。年度候选晋级前，旧季度文件先归档到 `01_core/memory-archive/`，归档哈希必须与源一致。

## 预算

按 Unicode 字符（`Array.from` 口径，含 Markdown 标题、符号和换行）统计：

```text
硬上限 = max(200, floor(8000 × 0.6^年龄))
压缩目标 = max(200, floor(硬上限 × 0.75))
```

当前年硬上限 8000、目标 6000；年龄 1/2/3/4/5/6/7 年的硬上限分别为 4800/2880/1728/1036/622/373/223，目标分别为 3600/2160/1296/777/466/279/200。年龄 8 年及以上固定为 200 字。超出目标但未超硬上限必须标记 `needs_review`，不能宣称无损。

每个候选旁的 `.memory-compression.json` 必须包含 5—10 条有代表性的 `coreDifferences`，每项至少有 `topic`、`original`、`candidate`、`kind`、`action`、`review` 六个字段。`kind` 继续用于内部审计并明确标注 `压缩/合并`、`删除`、`改动` 或 `保留`，但 comparison 的核心变化表不展示这一列。comparison 报告最前面必须先说明整份文件的实际减少量，再以精简表格展示 5—10 条核心变化的字数变化、之前内容和现在内容；按净减少字数从大到小排序，减少相同再按实际改动量排序。实际改动量按字符级对比计算为删除字符数加新增字符数，因此净减少不超过 10 字但替换超过 10 字的实质改写仍进入核心表。核心变化应覆盖代表性的合并、删除候选和实质改写，不是只挑最高层的几个主题。实际改动量不超过 10 字的变化不逐条展开，按变化类型归类；超过 10 字但未入选核心的变化也只做汇总。报告另设“其他压缩内容概览”章节，概括未纳入核心表的内容和具体例子；报告必须解释核心摘要字数与整份文件实际压缩量不是同一口径，缺失或字段不完整时标记 `needs_review`。

每个候选还必须提供 `otherChanges`，每项包含 `topic`、`before`、`after`、`examples`，用于解释核心表之外的总量差额。缺少该概览时，报告不能把候选标记为 `ready`，也不能晋级。

## 具象锚点

重要、反复出现并承载证据或行动的具体词必须原样保留。合并的是重复判断和解释，不是把具体生活改写成抽象标签。至少保留每条证据/行动链中的一个具体锚点；如果几个词共同决定含义，则整组保留。锚点包括人物、地点、项目、活动、作品和方法名，例如 `出门`、`读书会`、`写诗`、`运动`、`真实聊天`、`玉溪`、`大理`、`AI Coach`。

例如，候选可以把多周的内容合并为“出门、运动、自然、朋友、写诗、真实聊天和创作现场恢复生命能量”，但不能只写成“真实现场提供反馈”；可以合并读书会的重复判断，但不能只写成“共同产物”或“高质量关系”。抽象词可以作为上位总结，不能替代全部具象证据。若候选改写、删除或无法保留关键锚点，必须在 comparison 的差异和人工问题中明确标出，不能当作普通去重。

## 语义处理顺序

1. 删除完全重复内容。
2. 合并同一判断在不同周/月的重复表达，并保留全部来源标签。
3. 压缩旧月份的解释性冗余。
4. 最后才处理独立判断；独立判断、限定、反例、反转、隐喻和行动边界不得静默删除。

不确定的合并或删除写入 comparison 报告的问题与保留建议，交给用户修改。校验器通过只表示格式、哈希、保护块和预算检查通过，不表示语义等价已证明。

## 命令

```bash
npm run memory:compress -- --as-of YYYY-MM-DD
npm run memory:compress -- --validate <候选文件或目录>
npm run memory:compress -- --promote <候选文件或目录> --confirm
```

月度重复运行时，已有且源未变的候选保持不覆盖并报告待人工审核；源变化则标记 `stale`，不覆盖用户修改。`--promote --confirm` 重新读源、校验保护块和候选覆盖，归档后以临时文件原子替换并读回验证。定时任务永不自动晋级。
