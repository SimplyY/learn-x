# Action Feedback 周报规则

Action Feedback 是每周中间产物，不是最终 Weekly Output 的完整章节。

## 输入与聚合

- 只读取当前季度《核心议题总览》的「短期核心议题」，保持原始顺序；长期、中期议题不进入主表。
- 周报路径：`04_output/_dist/weekly/YYYY-Www/action-feedback.md`。
- 模板不得覆盖已有报告，不得自动新增人生议题；核心议题镜像缺失时标记 `needs_review`，不伪造空议题。

## 用户可见格式

```markdown
# Action Feedback 周报｜YYYY-Www

| 短期核心议题 | 行动 | 反馈 |
|---|---|---|
| <短期议题> | [ ] <行动> | <反馈> |
```

- 全文不超过 1000 字；五个或当前实际全部短期议题必须出现。
- `[ ]` / `[x]` 只表示是否确认写入 Base，不表示任务状态。
- `—` 表示本周没有新事项；缺失来源不可伪装为 `—`。
- 同一周、同一议题、同一行动的多条反馈合并在同一事件；不展示状态、反馈类型、下一步、证据、时间字段。

## Base 事件

每个确认行是一个事件：`目标周 + 短期核心议题 + 行动 + 反馈`。事件字段为：`短期核心议题`、`行动`、`反馈`、`周期时间`、`事件创建时间`、`事件键`；显式迁移还会确保后台时间分组公式字段 `年`、`月`、`年度第几周` 存在。`事件创建时间`是 Base 自动生成的系统时间；旧 Base 中同名普通 datetime 字段 `创建时间` 保留兼容，不作为新事件时间依据。事件键为 `sha256(目标周 + 议题 + 规范化行动)`；同周重跑更新，同一行动跨周生成新事件。

旧状态类字段只兼容历史记录，不驱动新周报。写入后必须按事件键读回校验。线上旧 Base 先显式运行 `action:feedback -- migrate` 新增字段，不自动批量迁移历史记录。

## Weekly Output 消费

最终 Weekly Output 优先读取已确认 Action Feedback，把真实行动和反馈作为高优先级现实输入，但不设置数字权重、不复制完整三列表格、不自动写入 Memory。
