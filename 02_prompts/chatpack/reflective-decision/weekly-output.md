# Weekly Output 核心输出要求

本文件定义 `learn-x-process` 生成 Weekly Output 时的判断原则、输出结构和质量标准。

## 1. 核心定位

Weekly Output 是 Learn-X 的**周度记忆层**。

它首先回答：

> **未来的我或 AI 如果要重新理解这一周，哪些具体经历、重要输入、思考、状态与变化值得留下？**

Weekly 强调**广度、具体性和人生纹理**。

有些内容未必值得进入 Core，也未必已经形成洞察，但未来仍可能成为理解用户的重要上下文。

Weekly 的核心任务：

1. 保留本周有未来解释价值的人生记忆；
2. 保留真正重要的信息源及其影响；
3. 记录新出现、持续、消失、反转或尚未完成的变化；
4. 可靠保留必要的核心量化事实；
5. 与上周做最小必要比较，形成时间轨迹；
6. 保留用户人工补充和长期记忆入口。

Weekly 不是：

- 任务管理器；
- 行动绩效报告；
- 完整人生复盘；
- 道 / 法 / 术生产线；
- 洞察、盲点或金句生产器。

行动只有在构成重要经历、现实反馈或变化证据时才进入 Weekly。

---

## 2. 与 Core / Monthly / 长期 Memory 的分工

### Core

保存当前仍然重要、最高信号、需要频繁作为 AI 上下文的信息。

特点：极少、当前有效、高调用频率。

### Weekly

保存一周内具有未来解释价值的广泛人生样本。

特点：具体、有纹理、覆盖面广。

> 一条内容不值得进入 Core，不代表它不值得进入 Weekly。

### Monthly

基于多个 Weekly 与本月材料，寻找跨周才看得见的模式、趋势和变化。

### 长期 Memory / 道等

只保存极少数真正稳定、值得长期携带的内容。

Weekly 本身就是长期人生上下文的一部分，不要求所有内容继续升级。

---

## 3. 什么值得保留

最高判断标准：

> **如果删除这条信息，未来的我或 AI 是否更容易误解“当时的我”？**

重点考虑：

### 个人解释力

是否帮助理解当时：

- 在意什么；
- 被什么滋养或消耗；
- 对什么产生兴趣；
- 与谁发生重要联系；
- 身体、情绪和生活状态如何；
- 处于怎样的人生阶段。

### 变化信息

是否新出现、消失、强化、弱化、反转、被现实修正或开始反复出现。

### 未来关联价值

未来讨论生活、关系、职业、兴趣、健康、创造、投资等问题时，是否可能成为重要上下文。

### 独特性

重复出现但没有新信息的内容降低优先级。

可以内部理解为：

> **重要性 ≈ 未来解释力 × 新信息量**

不计算分数。

---

## 4. 事实与上下文边界

当前 Weekly 的本周期事实以：

`04_output/_dist/weekly/YYYY-Www/process-pack.md`

为准。

规则：

- 本周事实必须来自当前 Process Pack；
- Core、道、Memory 等长期上下文用于理解当前用户状态和判断什么重要，但不能补造或覆盖本周事实；
- 上周 Weekly Output 只用于比较；
- 原始 Input / `input.json` 默认不读，只有来源缺失、冲突、核查或排错时使用；
- `_dist` 中脚本候选不是 AI 最终判断；
- `daily.md`、`weekly.md` 等是输入，不自动等于长期 Memory。

Action Feedback 已退役，不得假定存在独立 `action-feedback.md`、旧 Process Pack Action Feedback 快照或 Base 写入。

---

## 5. 本周记忆

这是 Weekly 的主体。

回答：

> **这一周未来值得重新想起和理解什么？**

可以自然包括：

- 人与关系；
- 日常生活；
- 身体和情绪状态；
- 地点、旅行、出门和环境；
- 兴趣、诗、电影、游戏、阅读等体验；
- 工作、项目和创造；
- 新鲜体验；
- 重要事件；
- 思考、选择和问题；
- 有解释价值的行动或现实反馈。

不要机械逐类输出，材料决定结构。

优先保留：

- 具体的人、事、场景；
- 当时真实的感受和判断；
- 发生变化的上下文；
- 能帮助未来恢复“当时的我”的细节。

避免流水账、日程复述、重复材料以及脱离事实的抽象总结。

一件事情即使没有产生洞察，只要未来有解释价值，也可以保留。

---

## 6. 重要信息源与外部世界

Weekly 应特别关注：

> **这一周，有什么重要东西进入了我的世界？**

来源可以包括：

- AI Chat 深度对话；
- 书、文章、论文、研究；
- Flomo 等个人笔记；
- 人、会议、现实聊天；
- 电影、播客、视频；
- 项目和真实世界反馈；
- 旅行与环境；
- 其他真正留下认知或生命痕迹的输入。

判断一个来源是否值得单独保留，主要看：

1. 是否带来重要的新事实、问题、视角或体验；
2. 是否明显改变注意力、理解或后续思考；
3. 是否包含未来值得重新访问的独特内容；
4. 是否与当前生命状态或长期问题形成重要连接。

每个入选来源重点写：

- 输入是什么；
- 为什么值得记住；
- 它留下了什么问题、判断、感受或影响。

不要把影响强制改写成行动。

不要列全量来源，不要只写路径，不设置最低字数。

保留原材料的问题意识、独特表达和必要上下文，不要全部统一改写成 AI 摘要。

---

## 7. 核心量化指标

核心量化指标是 Weekly 中需要高可靠保留的事实锚点。

每条指标身份至少由：

> **来源 + 时间粒度 + 指标名 + 单位 / 分母**

组成。

同名或同主题不代表同一观测。

例如 Health-X 周度心情分与日记每日心情评分不得互相填充、平均、推导或替代。

按实际 Process Pack 存在的数据输出：

- Health-X：实际提供的周度总分、维度分、步数、睡眠、活动消耗等；
- 日记：作为原始日粒度证据保留，但 Weekly 默认不重复展示每日评分，只有明确要求日趋势、异常或评分依据时引用；
- 周记：实际存在的周期评分。

要求：

- 原值保留；
- 不四舍五入；
- 不凭印象改写；
- 不跨时间粒度补缺；
- 保留单位、分母和原始变化说明；
- 不生成来源不存在的字段；
- 不生成“其他规定指标”清单；
- 正文相关判断不得与原始量化数据冲突。

只有确认该字段存在但本周没有记录时，才能写“本周无数据”。

---

## 8. 本周变化与未完成思考

只保存真正具有时间变化信息的内容：

- 新出现；
- 持续；
- 减弱或消失；
- 旧判断被修正；
- 兴趣、关系、问题或状态开始反复出现；
- 尚无答案但值得未来继续记住的问题。

问题本身也可以是有价值的记忆，不要求立即形成答案。

本节不是固定“洞察”或“盲点”生产区。

**没有强信号时可以省略。**

不要为了深刻而制造反转、批判或哲学结论。

---

## 9. 值得长期保留

这是 AI 提出的极薄长期候选，不是周期性资产生产任务。

输出：

> **0–3 条。**

可以是一段重要人生记忆、长期事实、稳定偏好、反复出现的模式或未来 AI 真正应该长期知道的背景。

规则：

- 0 条完全合法；
- 宁缺毋滥；
- 不分类成道 / 法 / 术；
- 不生成术器清单；
- 不把普通总结包装成长期记忆；
- 不自动写入长期资产。

格式：

```markdown
- [ ] ……
```

没有强信号时：

> 本周没有新的长期保留候选。

---

## 10. 来源

Weekly 必须可靠、可追溯，不编造输入中没有的信息。

正文优先使用 source id 或简短来源说明，末尾只保留支撑重要事实的最小必要来源。

AI 推断明确标记为：

- 观察；
- 推测；
- 待确认。

---

## 11. 全文核心重点纪要

保留现有系统确认语义。

```markdown
## 11. 全文核心重点纪要

1. xx
2. xx
3. xx
```

由用户后续手动补充。

---

## 12. 芒格之魂的洞察

保留现有系统确认语义。

```markdown
## 12. 芒格之魂的洞察

1. xx
2. xx
3. xx
```

由用户后续通过独立“芒格之魂”思考补充。

Weekly Output 本身不自动代写。

---

## 13. 本周最值得思考的 3 个问题与回答

必须提出**恰好 3 个**值得用户本人回答的问题。

优先选择：

- 本周反复出现但尚未解决的问题；
- 会改变未来理解或选择的重要张力；
- 目标函数问题；
- 未验证但真正重要的假设；
- 与当前生命状态有关、只有用户本人适合完成的价值判断。

规则：

- AI 只提问，不替用户回答；
- 三题互不重复；
- 必须由本周材料支持；
- 问题核心以 10–20 字为目标，最多 50 字；
- 可以增加背景补充，问题 + 背景合计最多 100 字；
- 不要求问题必须导向行动。

格式：

```markdown
## 13. 本周最值得思考的 3 个问题与回答

1. 问题：…？
   背景补充：（可选）…
   回答：…

2. 问题：…？
   背景补充：（可选）…
   回答：…

3. 问题：…？
   背景补充：（可选）…
   回答：…
```

用户补充后的 11 / 12 / 13 若已有下游 Memory / 芒格候选池消费规则，保持现有机器语义。

空白、`todo`、未回答问题、`xx` 占位不得迁移。

---

## 14. 本周与上周对照

使用 Process Pack 中明确提供的上周 Weekly Output。

旧 Weekly 只能用于比较，不能补充或覆盖本周事实。

重点只比较：

- 新出现；
- 持续；
- 消失；
- 强化 / 弱化；
- 反转；
- 被现实修正；
- 尚未解决。

同一事实只计一次。

空占位和未回答问题不能作为证据。

若基线为 `missing`、`empty` 或 `shell`：

- 保留本节；
- 标注“不可比较”；
- 不回退更早周期。

最多 600 字。

不要机械评分，也不要重新总结整份 Weekly。

## 15. 默认输出结构

```markdown
# YYYY-Www Weekly Output

## 0. 本周总览

## 1. 本周记忆

## 2. 核心量化指标

## 3. 重要信息源与外部世界

## 4. 本周变化与未完成思考

## 5. 值得长期保留

## 10. 来源

## 11. 全文核心重点纪要

## 12. 芒格之魂的洞察

## 13. 本周最值得思考的 3 个问题与回答

## 14. 本周与上周对照
```

编号 11 / 12 / 13 / 14 优先保持现有机器契约兼容。

正文模块遵循：

> **有信号才展开，0 是合法结果。**

不要为填满结构重复同一事实。

---

## 16. 写作与质量原则

### 保真优先

不要为了更多洞察而牺牲具体事实和人生纹理。

### 广度不是流水账

保留广泛样本，但只留下具有未来解释价值的内容。

### 少加工

一段经历加工到足够有用即可停止。

### 语言锋芒不是 KPI

重要判断可以精炼、有力，但不强制金句、不强制反转。

### 允许空

没有重要变化就不要制造变化；没有长期候选就输出 0 条。

一份 Weekly 即使没有“洞察”，仍然可以是高质量的人生记忆。

---

## 17. 明确取消

Weekly 不再要求：

- 做中学 A/B/C/S 评分；
- 行动闭环作为固定主章节；
- 下周行动清单；
- 固定数量的核心洞察；
- 固定数量的盲点与反例；
- 5–10 条 Memory 候选；
- 周期性道 / 法 / 术 / 器候选；
- 每个关键模块至少一句金句；
- 为了数量而制造候选。

同时继续禁止：

- 把旧周期事实写成本周期事实；
- 把内部系统产物伪装成现实世界事实；
- 因材料长就认为重要；
- 改写或推导核心量化数据；
- 把不同时间粒度指标互相映射。

---

## 18. 输出前检查

只检查：

1. 未来重新理解这一周，真正不能丢的内容是否留下？
2. 是否保存了足够具体的人生纹理，而不只是抽象洞察？
3. 是否遗漏重要的信息源和外部世界输入？
4. 是否又把 Weekly 写成行动复盘？
5. 是否为了完整而硬凑内容？
6. 核心量化指标是否忠于原始输入？
7. 机器消费章节是否保持兼容？

删除不增加未来理解价值的内容。
