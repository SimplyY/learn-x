# Learn-X 周记草稿

从 `03_input/weekly/YYYY-Www/` 的已落盘材料生成飞书周记模板草稿。`03_input` 是事实快照；飞书仅提供模板、目标段落和草稿写入位置。草稿不是已确认周记，也不得触发 Input Pack、Process Pack、Weekly Output 或 Memory。（Action Feedback 已退役，不再有配套草稿。）

## 前置条件

1. 解析唯一目标周，使用 `Asia/Shanghai` 与 `learn-x-weekly-automation` 相同的规则。
2. 读取目标周目录；先读取 `_source-status.json`（存在时格式非法就停止），确认 `daily=ready` 且 `daily.md` 有效；再按 Flomo 状态决定是否打开 `flomo.md`。Flomo 可为 `ready` 或成功的 `empty`，AI 回顾为可选补充：

   - `daily.md` 必须带目标周范围、来源和采集信息，且不是空文件、模板或缺口说明。仅当 `flomo=ready` 时才打开 `flomo.md`；它必须带 `目标范围`（周一 00:00 含至下一周周一 00:00 不含，Asia/Shanghai）、`采集时间`、`记录数`、早于目标范围下界的 `最早已读取笔记时间` 和 `下界已覆盖：是`，并与侧车周、计数及状态一致，且不是空文件、模板或缺口说明。只有周六/周日自动选择当前周的提前稿可按采集文件声明的实际范围覆盖至运行日并列出未来缺失日期；这种文件不可充当完整周回顾来源。`flomo=empty` 时，侧车计数必须为 0，`summary` 须持久说明成功扫描的起止时间、`下界已覆盖：是` 及“0 条、确认无匹配”，且扫描范围符合目标周允许范围；不得打开磁盘上可能保留的旧 `flomo.md`。Flomo 为 `failed`、`unavailable` 或完整性无法确认时，不打开该文件，并停止周记生成。
   - 已确认的 `ai.md` 优先；若其无效或缺失，只能读取侧车状态为 `generated` 的 `ai.generated.md`，并明确它只是未确认草稿，不是正式输入。
   - `ai.md` / `ai.generated.md` 中的空壳、模板、提取提示词或自动缺口说明一律忽略，不作为阻塞。
   - 计算运行日期所在 ISO 周的上一周，作为最近一个已结束的完整周（Asia/Shanghai，周一至周日）。若它等于目标周，复用已通过本节校验的目标周 Flomo 状态；仅 `ready` 时使用其 `flomo.md`，`empty` 时只复用状态并保留模板提示。若不同，先读取来源周 `_source-status.json`，仅当 `flomo=ready` 时才打开并校验 `flomo.md`；来源必须覆盖完整周一至周日（不能使用周末提前稿的部分文件）。`ready` 且完整性字段、范围和记录数相符时使用全部笔记；`empty`、计数为 0 且 `summary` 含完整扫描起止时间、`下界已覆盖：是` 及“0 条、确认无匹配”时只保留模板提示并报告“0 条笔记”，绝不打开可能残留的 `flomo.md`。`failed`、`unavailable`、缺少完整性证据、范围不符或数量不符时，不打开旧内容；其他草稿字段照常生成，该字段保留模板空位并报告具体原因。目标周被手动指定时，回顾来源周仍按运行日期计算，并在汇报中同时标明目标周与来源周。
   - 本 Skill 不直接访问 ChatGPT；AI 生成由 `learn-x-weekly-automation` 调用全局 `chatgpt-web-bridge` 完成。
3. 可读取 `health.md`、`voice.md`、`weread.md`、`calendar.md`、`time.md`、`build.md`、`build-bot.md` 作为对应字段的补充证据；缺失时只标注待补，不以旧文件或推测填充。
4. `daily.md` 无效，或 Flomo 状态为 `failed/unavailable`、完整性无法确认时，停止并报告具体来源状态；成功的 `flomo=empty` 是有效空结果，不阻断周记生成，也不读取旧 `flomo.md`。不要读取线上周记作为事实替代。

## 证据与草稿

- Flomo 是语义主线：优先提取反复出现的判断、问题、转变和可行动线索。
- 日记是时间与事实骨架：用于发生过的行动、感受、出门/社交和身体状态。
- `ai.md` 存在时补充已确认反思；阶段 1 只有 `ai.generated.md` 时，可将其作为未确认草稿补充，但不得把其状态写成已确认事实；其他本地来源只补其能支持的字段。
- 草稿标记只放在目标周记的主标题：标题使用 `【待优化】AI 基础草稿：M.D`；正文细项、表格单元格、列表、引用和诗句不得重复该标记。不要捏造照片、评分、健康数据、投资、支出或已完成事项。
- “修身 & 修心”中的运动只写已有明确证据的数据；没有运动细项时直接省略，不输出任何运动待补占位语。
- “回顾最近笔记 & flomo 洞察”自动填入最近一个已结束 ISO 周（Asia/Shanghai，周一至周日）`flomo.md` 中的全部有效笔记，按创建时间顺序逐条保留原文和原有日期、时间、标签及笔记边界；沿用 `flomo.md` 已有的 Learn-X 生成内容过滤。不得按最近 7×24 小时滚动取数，也不得精选、总结、改写、截断或漏掉笔记。保留模板提示；仅替换该字段的空白/占位内容。成功空结果也视为有效：保留模板提示并报告 0 条笔记；不得将旧 `flomo.md` 当作本轮来源。若目标格已有实质人工内容或已有周记草稿，遵守停止门禁，不覆盖。
- “好诗”必须收录目标周 `flomo.md` 中全部带 `#写诗` 标签的笔记，按时间顺序保留原文，不遗漏、不凭主题猜测额外诗句。
- “一周核心总结”必须生成 2–3 个独立的直接列表项；每项只表达一个完整总结，不把多个编号句塞进同一个列表项。
- “核心收获&思考”必须生成 2–3 个独立的直接列表项；每项只表达一个完整收获，不在正文中手写 `1.`、`2.` 等序号。
- “新周计划”只使用一个有序列表：至多 3 条候选计划，再追加恰好 3 条 `TODO（待完善）：` 空列表项；列表项正文不写 `候选 1`、`候选 2` 或任何手工数字，编号只由飞书原生列表生成，不复用模板遗留的固定 `seq="1"`。

## 飞书写入

1. 使用 `lark-cli docs` 的 bot 身份读取文档大纲（周记草稿为 AI 代笔，读写统一 bot 身份）：

   ```text
   https://ywhome.feishu.cn/wiki/EOlbwTVLyiQp7Fkrr9ucdI9hnac
   ```
2. 根据目标 ISO 周计算结束日的下一天 `M.D`，定位 `周记` 下的目标段落。例如 `2026-W31` 覆盖 `2026-07-27`—`2026-08-02`，目标是 `8.3`。
3. 读取 `周记模版` 与目标段落的带 block id 内容；只把模板和现有目标段落用于结构与安全写入，不从其中提取事实。
4. 目标段落存在任何实质性人工内容，或包含已有草稿时，停止并报告该段落链接；不覆盖、不自动刷新、不追加第二份草稿。
5. 目标段落缺失时，复制“周记模版”的标题与表格块到 `周记` 下合适位置，再逐块填写仅限新复制模板中的空白/占位项。不得重建表格 XML，禁止 `overwrite`。
6. 填写时只使用明确可验证的字段：

   - `照片/朋友圈`：仅使用日记或周输入中的相关文字；没有证据则保留待补。
   - `修身&修心`：仅使用健康、日记、时间等明确记录。
   - `回顾最近笔记 & flomo 洞察`：粘贴来源 `flomo.md` 中符合既有过滤边界的全部笔记原文；不做语义加工。成功空结果保留模板提示。
   - `一周核心总结`、`核心收获&思考`：使用目标周的 Flomo、日记和存在时的 `ai.md` 交叉校验；不要将总结写回原始笔记列表。
   - `好诗`：收录 Flomo 中全部 `#写诗` 笔记；若没有该标签笔记才保留待补。
   - `一周核心总结`：2–3 个直接列表项；`核心收获&思考`：2–3 个直接列表项；两处都不手写数字编号。
   - `新周计划`：一个有序列表，最多 3 条候选与恰好 3 条待完善 TODO；候选项只写 `候选｜...`，编号交给列表结构。
   - 写入整周笔记前，核对完整内容是否能被当前 `lark-cli docs` 更新方式承载。只有工具明确支持在同一单元格内按完整笔记边界分批更新并逐批回读时，才可分批写入；否则无法安全承载时不改该字段，报告笔记条数和内容长度。任一回读不完整时停止，不盲目追加、不截断；仅在能精确恢复原模板空位并回读确认时恢复，否则报告当前落地状态。
7. 每次 block 更新后重新读取目标段落；验证只改动目标段落并保留模板表格。对“回顾最近笔记 & flomo 洞察”核对来源周为运行日期前最近一个完整 ISO 周、采集状态与记录数可信、覆盖完整周一至周日，笔记数量、顺序和原文边界与来源 `flomo.md` 一致，模板提示仍保留；成功空结果须报告 0 条且不伪装为失败，来源不完整时确认字段仍为空位且缺口已记录。只有主标题有草稿标记，正文细项没有重复标记。对三个有序列表分别核对：核心总结 2–3 项、核心收获 2–3 项、计划候选 ≤3 且 TODO=3；正文无手工数字，列表编号连续且不重置。
8. 生成后必须重新 fetch 目标段落并生成直达链接：优先使用飞书实际产生的 `#share-...` 锚点；CLI 未返回 share 锚点时，使用刚回读得到的目标标题 block id 构造 `文档基础 URL#<target-block-id>`。汇报只能使用这个本次回读确认的目标段落链接，不得输出固定文档首页、旧周锚点或未带 fragment 的 URL；如果无法取得并验证锚点，链接状态记为阻塞，不得伪造链接。

## 人工确认与汇报

- 用户编辑并确认飞书周记时，应移除主标题中的 `【待优化】AI 基础草稿` 标记；标题标记仍存在即视为未确认，不能进入 Weekly Process。
- 汇报必须包含目标周、周记草稿的事实来源、Flomo 回顾来源周和完整日期范围、笔记条数与生成/跳过字段、本次回读确认的飞书目标段落锚点链接、阻塞项、当前位置、下一步和再下一步。若回顾来源不可用，明确指出该字段未填和具体缺口。
- 成功后提示用户在飞书编辑周记并审核；回复“周记已确认”或“继续生成周报材料”表示周记草稿已通过（Action Feedback 已退役，不再有配套草稿）。此 Skill 本身不采集 `weekly.md` 或生成 Process Pack。
