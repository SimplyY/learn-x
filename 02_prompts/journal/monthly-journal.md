# Learn-X 月记草稿

从本地 `03_input/weekly/YYYY-Www/` 与 `03_input/monthly/YYYY-M/` 生成飞书月记模板草稿。周目录是可追溯事实快照；飞书仅用于读取模板、定位目标月并写入草稿。草稿不是 Monthly Output，也不得生成 `_dist` 或 Memory。

## 前置条件

1. 解析目标月：默认 `Asia/Shanghai` 上个月，用户指定 `YYYY-MM`、本月或上月时按用户指定。月度目录始终使用 `03_input/monthly/YYYY-M/`。
2. 找出所有与目标月相交的 ISO 周。读取每周 `_source-status.json`（若存在，格式非法即停止）；被标记为 `empty/failed/unavailable` 的自动来源旧文件不得读取。将周分为“已确认可聚合”和“待人工补齐”两类；月份首尾仅部分落入目标月的 ISO 周属于边界周。常规周记和其他来源的边界周内容只在汇报中提示，不写入飞书月记；精读 `jingdu.md` 按第 3 条的明确日期规则处理：

   - 已确认周必须有目标覆盖范围、来源和正文，且不是空文件、模板或缺口说明。
   - 缺失、为空、模板化、缺少核心总结/收获或含 `【待优化】AI 基础草稿` 的周，标为“待人工补齐”，不作为已确认事实；它们不阻塞生成部分月记草稿。
   - 缺口必须在结果和汇报中醒目标记；月内完整周的缺口可作为人工待办，边界周缺口仅作提示，不要求补齐、不写入月记正文或表格。非法侧车或无法判断来源完整性仍停止，不能把损坏数据降级成普通缺口。
3. 只读取这些本地来源，并按目标月日期过滤边界周内容；待人工补齐周的未确认 `weekly.md` 不进入已确认事实，边界周即使缺失也不人为补写：

   - 已确认 `weekly.md` 是最高权重的人工作业压缩层。
   - `daily.md` 提供事实/状态时间线，`flomo.md` 提供语义主线，`ai.md` 提供人工反思补证。
   - `health.md`、`voice.md`、`weread.md`、`calendar.md`、`time.md`、`build.md`、`build-bot.md` 仅在字段相关且有明确证据、且状态为 `ready`（或历史周没有侧车）时补充。
   - `jingdu.md` 仅在该周来源状态侧车明确标记其为 `ready` 时读取和使用。`empty` 不阻塞；状态缺失/未知，以及 `needs_review/failed/unavailable` 或标记保留旧文件时，不读取该文件、不把其中内容作为事实，并在汇报中说明。不能因为历史周没有侧车而放宽这一来源门禁。
   - 对完整落在目标月内的周，`ready` 的 `jingdu.md` 按周输入使用。对跨月边界周，必须逐条检查精读记录自身明确的日期，只纳入日期属于目标月的条目；目标月外、日期缺失或无法确认的条目一律排除并在汇报中说明。不得按周覆盖范围推定条目日期，也不得使用通用过滤器在没有日期分段时返回的全文 fallback 作为目标月精读内容。
4. 复用 `monthly-process-input.mjs` 的选择语义：按正文日期、声明覆盖期和周记标题过滤月外内容，合并日记元数据、按日期去重 Flomo；不按文件 mtime 推断范围，不创建空周目录，不猜测缺失内容。
5. 不读取 Daily Base、线上周记或其他飞书材料作为事实源；它们的后续编辑不应改变已落盘月度证据。

## 草稿生成

- 保持证据优先级：确认周记总结月度主线，Flomo 提炼反复出现的判断与变化，日记校验发生过的行动/状态，`ai.md` 补足已形成的反思。
- 只在月记现有“学习”分类中使用 `jingdu.md`：保留理解所需的书名或原划线等上下文，但结论必须基于本人对精读的理解、判断或可选行动；不能把未加工的原始划线单独写成用户观点，也不新增“精读”章节。
- 只填写有明确证据的月记字段；照片、评分、健康指标、投资、支出、社交或计划没有证据时保留待补。草稿可以基于已确认周和安全的月度来源先行生成，但不得替待人工补齐周补写事实。
- 草稿标记只放在目标月记的主标题：标题使用 `【待优化】AI 基础草稿：YYYY-M`；正文细项、表格单元格、列表、引用和诗句不得重复该标记。
- 健康字段只写已有明确证据的数据；没有运动细项时直接省略，不输出任何运动待补占位语。
- 严格沿用 `月记模版` 的现有结构，只填写模板已有字段，不新增周记专属的“回顾最近笔记”“好诗”“一周核心总结”或“核心收获”章节；这些内容只属于周记。
- 模板中的“核心总结”保留原有六个分类项（投资、出门、教育、学习、娱乐、社交）和“一句话总结”段落；不要把月记模板改造成周记结构。
- 新月计划只使用一个有序列表：最多 3 条候选，并追加恰好 3 条 `TODO（待完善）：` 空列表项；编号只由飞书原生列表生成，不复用模板遗留的固定 `seq="1"`。

## 飞书写入

1. 使用 `lark-cli docs` 的用户身份读取月记文档大纲：

   ```text
   https://ywhome.feishu.cn/wiki/EOlbwTVLyiQp7Fkrr9ucdI9hnac
   ```
2. 只读取 `月记模版`、`月记` 和目标月段落的带 block id 内容，用于识别安全空位和写入位置；不得从线上日记或周记提取事实。
3. 目标月已有实质内容或已有草稿时停止并报告链接；不覆盖、不自动刷新、不追加第二份草稿。目标月缺失且有安全空位时，即使存在待人工补齐周，也可以写入带 `【待优化】AI 基础草稿` 的部分草稿，并在汇报中提示缺口；边界周缺口提示只能出现在 Codex 汇报，不得写入飞书月记正文或表格。符合第 3 条日期和状态门禁的 `jingdu.md` 目标月条目可作为月记事实写入。
4. 目标月缺失时，复制 `月记模版` 的标题与表格块到 `月记` 标题之后、所有已有月份之前；月记按月份倒序排列，不能把新月份插到最近月份标题之后或其正文内部。只填写新复制模板中的空白/占位项。不得重建表格 XML，禁止 `overwrite`。
5. 只用 `block_replace` 更新明确为空或占位的段落/列表项；每次更新后重新读取目标月段落。无法确认安全写入位置时停止。
6. 验证只改动目标月、只有主标题有草稿标记、正文细项没有重复标记，且原有人工内容未变；核对核心列表、收获列表和计划列表的数量与连续编号。

## 后续阶段与汇报

- 人工确认月记时应移除主标题中的草稿标记；标题仍有标记即不允许进入月度阶段 2。
- 阶段 2 才从线上目标月段落采集最终 `monthly-journal.md`；这不是重新采集月度事实。
- 汇报必须包含目标月、已确认周范围、待人工补齐周、使用的本地来源、飞书草稿链接、缺口提示、当前位置、下一步和再下一步。若相交周存在 `jingdu.md`，还要报告其来源状态、纳入的周范围/条目，以及跨月周中因月外日期、日期缺失或日期无法确认而排除的条目；`empty` 不阻塞，其他非 `ready` 状态说明跳过原因。边界周缺口必须醒目提示但不得列为门槛或要求补齐；其它缺口是人工待办，不等同于草稿生成失败。
