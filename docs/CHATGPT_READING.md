# Learn-X｜ChatGPT 阅读上下文使用说明

## 飞书微信读书采集

在 Learn-X 飞书群发送单条文本消息：

```text
整理最近 3 天微信读书划线和想法
```

指定日期范围或书籍时，在消息中写清起止日期、书名或书籍 ID。默认范围按 Asia/Shanghai 计算。结果应分别说明实际采集范围、取得数、精选数和局部缺口；只有本地写入并读回后才显示“本地已保存”。

需要立即伴读时，从本次结果复制完整伴读包到 ChatGPT；不必等待 GitHub 同步。仅当有实际远端提交和读取证据时，才把内容称为“GitHub 已同步”。

伴读包正文目标为 3000～6000 字。原文合计不超过 3000 字时逐字保留全部划线和想法；超过后才允许压缩，压缩比例不超过 30%，不得改写原意或把概括冒充原文。

修改记录时发送 `修改 <recordId> <具体修改>`；撤销时发送 `撤销 <recordId>`。使用结果收据中的记录 ID。实体书照片、OCR 与圈注/划线识别目前按用户要求暂缓。

截至 2026-11-03，已用真实微信读书数据完成两批采集与交付：同一本书累计 10 条唯一来源记录、0 条个人想法；第二次飞书请求由 Bridge 自动运行 Skill，更新本地阅读记录和飞书阅读文档，并送达结果卡。文档与卡片均通过 API 读回；第一次触发曾遇到 MoonBridge 预检失败，后续由 Codex 手动接续。手机界面、修改/撤销交互和 GitHub 同步仍未验收；没有 Commit 或 Push。未收到实际结果卡时，不要推定本次内容已保存或已送达。

## 固定 GitHub 阅读索引

每周精读从公开仓库入口开始：

`https://github.com/SimplyY/learn-x/blob/main/05_library/reading/_index.md`

使用时先读取索引，再按本次真实范围打开对应书籍 Markdown：

- 未指定范围：读取最近七天内有阅读记录的书籍和条目，必要时延伸到相关历史记录。
- 指定单本或多本书：只读取明确要求的书。
- 指定章节：定位到相应章节并报告范围。
- 伴读包：直接使用用户贴入的完整包；它可能包含尚未进入 GitHub 的本地新增内容。

ChatGPT 必须报告实际取得的书名、章节/日期、文件路径和 GitHub commit 或文件版本证据。若当前会话无法访问仓库，说明读取失败并请用户粘贴飞书伴读包。不得把本机未推送内容或 ChatGPT Memory 说成已读取的 Learn-X 文件。Memory 用于辅助理解，不视为实时 Flomo 全量快照。

## 精读 Prompt

在 ChatGPT 对话中粘贴受治理 Prompt [`../02_prompts/meta/chatgpt-reading-weekly.md`](../02_prompts/meta/chatgpt-reading-weekly.md)（`learn-x.reading-weekly`）。用户可直接从对话历史的阅读卡复制本次伴读包，避免重复整理。每次真实阅读的范围和可得性优先于推测。

精读每周推荐 2～5 个有具体阅读依据的 Flomo 思考方向，每条约 50～160 字、每段不超过 80 字。材料不足时减少条数。用户自行决定是否及如何手写或语音记录，AI 不写入 Flomo。

## 日常伴读包生成 Prompt

`learn-x.reading-daily` 是 Learn-X 生成伴读包时读取的受治理 Prompt，不是用户单独粘贴给 ChatGPT 的 Prompt。生成包末尾自带简短的「ChatGPT 伴读 Prompt」，用户把伴读包粘贴到 ChatGPT 即可。

## 飞书提醒配置文案

由用户自行在飞书配置每周三 08:30（Asia/Shanghai）提醒，不由 Learn-X 自动创建或管理提醒。

提醒正文：

> 每周精读时间。打开 ChatGPT，基于 LearnX 最新阅读上下文与可用记忆，深入理解核心观点、思想基石及重要反例。最后给出 2～5 个具体 Flomo 思考建议。我自己选择、思考并记录。

ChatGPT 精读始终由用户手动发起。
