# ADR 0003：统一阅读上下文与旧精读退役

- 状态：Accepted（2026-11-03，按用户冻结需求与后续实施指示）
- Requirement：[LearnX 统一阅读沉淀与 ChatGPT 精读](../requirements/2026-11-unified-reading.md)
- Case：[LearnX 统一阅读](../cases/2026-11-unified-reading/case.md)
- Supersedes: ADR 0002 中 `jingdu` 作为当前周输入源的决策；不改变 WeRead 存量归档决定。

## 背景

微信读书划线、实体书照片和 AI 阅读对话缺少统一、可持续读取的阅读上下文。原周度 `jingdu.md` 流程交互较重，且会把阅读重新塞入周输入链。新需求将日常积累、ChatGPT 精读和用户自己的 Flomo 思考分开。

## 决策

1. 日常微信读书阅读只采集用户指定范围；默认使用 Asia/Shanghai 最近三天。采集保留实际范围、稳定来源 ID、取得数量和不完整原因。电子书精选由 Skill 完成，不把精选数报告为原始全量。
2. 精炼阅读上下文按书保存到 `05_library/reading/`，使用 `_index.md` 定位；私有状态、待处理结果和伴读包放入 Git 忽略的 `.runtime/reading/`。公开同步仍由既有 Git 机制负责，阅读采集不执行 Git 操作。
3. ChatGPT 精读读取实际已推送的 Learn-X 文件；本地未推送新增内容不冒称远端已读。当前批次可通过飞书伴读包直接交接。
4. 用户明确要求后，允许按记录 ID 和当前版本修改或撤销；旧版本冲突不得覆盖。撤销本地文件不意味着清除公开 Git 历史。
5. 旧 `jingdu.md` 不再生成、登记或进入周/月消费。历史文件及侧车读取兼容保留；周日旧精读自动化停用。原始 WeRead 周采集、WeRead 存量归档、Flomo 和其他周/月功能保留。
6. 实体书照片、OCR 和视觉标记识别按用户 2026-11-03 的后续指示整体暂缓。本地 store 不接受 physical 来源；恢复前不建设该入口。
7. 周三 08:30 提醒由用户自行配置，ChatGPT 精读由用户手动发起；Flomo 只由用户亲手写入。

## 后果与待完成事项

- 阅读上下文主要供模型读取，避免建设独立阅读平台或跨周期知识数据库。
- 公开 Markdown 默认适合 GitHub；敏感或明确不公开内容必须留在私有运行区。
- 当前工作树已实现 WeRead 范围采集、本地保存、去重、版本化修改/撤销和旧消费过滤；飞书自动触发、每书 Docx、交互式结果卡/修改回调及 GitHub 端到端读取仍待接通与验收。
- 月记 latest Prompt 的治理发布本轮未确认成功。运行时 Skill 已加退役保护，远端真源保持原 revision，不能宣称发布完成。

## 被否决方案

- 继续把新精读生成到周输入 `jingdu.md`：会维护重复系统并让周/月消费者误把旧产物当新结果。
- 把图片 OCR 文本当成实体书全部明确标记：无法证明划线、括号、圈注均被识别；且用户已明确暂缓这部分。
- 在采集 Skill 内增加 Git 提交/推送、Flomo 自动写入或新的知识数据库：超出需求并增加隐私与维护面。
