## 状态

- 类型：Minor
- 状态：已确认，规则已实施；样本级验证受限
- 目标：为 Learn-X 月记草稿增加周度精读（`jingdu.md`）作为证据来源。

## 需求来源与范围裁决

### 原始请求

> 月记的输入源你参考一下周记少了哪些东西，以及未来还要引入哪些东西 core 中的核心内容，周记也是一样，你可以去读一下 core 的方案设计文档，总之，我觉得上下文非常重要。你先设计一个方案吧，当然我们一起对一下：月记输入源和周记输入源需要补什么东西。

### 后续范围澄清

> 啥意思？具体有哪些内容要补齐到方案中？以及哪些接入到周记，哪些接入到月记？我理解应该是接入到月记吧。先不管周记，是参考周记。调用 ywplan skill 重新设计。

经后续方案对齐，当前实施范围收窄为：**只给月记草稿增加周度精读来源；周记只作为来源规则参考，不改周记流程。** Core 及其他候选来源不属于本需求，不接入月记或周记。

## 需求

月记草稿生成时，应能将目标月范围内、状态为 `ready` 的周输入 `jingdu.md` 作为现有“学习”分类的证据，补足周记来源清单未覆盖的精读材料。

精读记录应以本人参与加工的内容为依据，包括本人理解、判断或可选行动，并保留理解这些内容所需的书名、原划线等上下文。原始划线本身不能被改写成用户观点。

## 范围与规则

- 修改月记草稿 Skill 中的来源清单、使用规则、边界处理与运行汇报要求；并对月度自动化 Skill 的调用门禁增加仅适用于显式 `ready` 精读条目的窄例外，避免上层规则阻止已确认行为。
- 仅读取来源状态为 `ready` 的 `jingdu.md`；`empty` 不阻塞。失败、不可用、待审核、状态不明或旧状态文件内容不作为本轮事实，并在汇报中说明。
- 与目标月相交且完整落在目标月内的周目录，按现有规则读取精读内容。
- 对跨月周，逐条核对明确日期；仅纳入日期明确且属于目标月的精读条目。月外、日期不明的条目排除，并在运行汇报中说明。
- 精读内容只进入月记现有“学习”分类，不新增“精读”章节或模板字段。
- 不改周记流程、采集器、Monthly Process Pack、月记模板、其他来源规则或飞书月记内容。
- 不接入 Core、Coach、智慧之门、微信、飞书文档或其他候选来源。

## 验收标准

1. 月记草稿 Skill 明确列出 `jingdu.md` 来源及 `ready` 门禁。
2. 月内周精读按现有规则纳入；跨月周仅纳入有明确目标月日期的条目。
3. 月外和日期不明条目不被写入，并在汇报中报告相应缺口。
4. 非 `ready` 的旧文件不作为本轮事实；`empty` 不阻塞。
5. 精读证据映射至现有“学习”分类，原始划线不单独代表用户观点。
6. 周记流程、月记模板、采集器、Monthly Process Pack 与飞书文档无改动。
