## 需求基线

- R1：全部登记 Prompt 与 Core《道／法》均缓存 14 天。
- R2：服务启动全量读取、每日刷新；每次生成也请求后台全量刷新。
- R3：全部刷新入口共用滚动 60 秒节流和并发去重，保留手动刷新。
- R4：缓存状态、缓存年龄、更新进度与错误须在生成按钮附近可见。
- R5：缺失、过期、身份或正文校验失败时，先刷新；必需资源刷新失败时停止本次生成。每项成功时间独立更新。
- R6：本地持久缓存须在进程重启后保留，错误须可观察和恢复。点击立即显示阶段状态；对等待、复制失败、重复操作和旧请求覆盖设置明确处理。
- 实现限于本地 Chat Pack 运行时；共享 Prompt 和 Core 读取器及其他自动化仍按其既有实时语义运行。
- 用户确认全量预取，而非只加载当前选中项；手动刷新仅用于少量需要立即更新的场景。
- 不新增数据库、外部缓存或新的常驻进程。状态与刷新合并方案详见完整 Execution Plan。
