# 深度研究系统

深度研究是 Learn-X 的一等研究资产：**一次深度研究 = 一篇 Wiki 文档**，保存在私有 Wiki「人生核心议题」的年目录 `深度研究-YYYY` 下，按年归档。系统要回答四个根本问题：

1. 我现在怎么看？（议题的当前判断）
2. 过去系统研究过什么？（深度研究文档）
3. 我的判断为什么发生变化？（认知事件）
4. 下一步最值得研究、验证或行动的是什么？（议题的下一步 + 研究文档的下一步）

## 对象模型

| 对象 | 载体 | 职责 |
| --- | --- | --- |
| 议题 | Base `议题` 表 | 长期问题/目标；只维护当前判断快照，不保存历史正文 |
| 深度研究 | Wiki 文档（本目录） | 研究资产本体；一次研究一篇文档，含完整上下文与分析过程 |
| 认知事件 | Base `认知事件` 表 | 判断变化历史；`来源链接` 指向触发它的研究文档 |
| 当前判断 | `议题` 表字段 | 最新认知快照；历史变化全部由认知事件承担 |

研究与议题是**多对多**关系，体现在文档模板的注入区块中；不新增 Base 表或字段。现实经历可以直接产生认知事件，不要求必须来自研究文档。

## 三层机制彻底解耦

- **季度总览**：战略盘点——有哪些长期、中期、短期核心问题？优先级如何变化？
- **月度工作台**：注意力调度——这个月哪些问题值得重新进入注意力？月度推送 ≠ 深度研究。
- **深度研究**：按需发生——一个月 0 篇 / 1 篇 / 多篇，由真正的问题触发，不绑定月份或季度。

```text
季度盘点 → 月度调度 → 议题 → 一键深度研究 → 研究文档
                ↑                              ↓
                └── 认知事件 ← 研究/思考/现实反馈 ←┘
```

这是一条循环，不是一次性流程。

## 一键深度研究

入口：某个核心议题、某个月度推荐、一个临时问题、某次认知事件或现实经历。执行 `npm run inquiry:deep-research -- create --title 主题 [--issue-id IQ-0001]... [--question 问题]`，系统自动完成：创建 Wiki 文档、注入研究模板、带入当前判断/最大未知/近期认知事件、重建目录索引、返回链接。**自动化发生在研究发起时，不存在研究结束后的回填管线。**

运行细节见 [Skill](../.agents/skills/learn-x-deep-research/SKILL.md) 与 [研究契约](../.agents/skills/learn-x-deep-research/references/research-contract.md)。

## 研究文档模板

模板只提供框架和脚手架，固定八个检查点，不固定研究方法：

1. **研究问题**：这次究竟想弄清什么？
2. **为什么现在研究**：触发背景、现实约束、关联议题。
3. **当前认知**：研究开始前我怎么看待它？（脚本自动注入）
4. **研究主体**：自由研究区，按主题动态展开。
5. **反证与未知**：哪些证据可能推翻当前判断？哪些问题无法回答？
6. **阶段性结论**：目前能确定什么？哪些只是推断？
7. **认知变化**：与研究前相比，判断改变/加强、问题重构、新决策或行动。
8. **下一步**：还有什么值得继续研究、验证或行动？

## 自动化边界

- **应自动化**：创建文档、注入模板、汇集上下文、拉取历史事件、保存链接、维护目录索引、生成 ChatGPT 上下文包（`context` 命令）。
- **AI 辅助但需人工确认**：是否真的产生认知变化、提炼认知事件、更新当前判断、识别问题重构、推荐下一步方向。
- **不自动化**：什么值得研究、是否相信结论、价值判断、最终决策、是否行动、如何解释自己的生命经验。

核心原则：**自动化研究之外的一切，把人的注意力留给研究本身。** 系统清除研究周围的行政成本，而不是替人研究。

## 非目标

- 不新增多维表格，不改 Base 结构；本能力对 Base 只读。
- 不建研究结束后的回填/apply/rollback 管线；认知事件由人（或经确认由 agent）在 Base 记录，`来源链接` = 研究文档 URL，`来源系统` = Learn-X。
- 不与月度工作台耦合：月度推送只是深度研究的可能入口之一。
- 深度研究待办表继续作为待研究池使用，是否长期保留待真实使用后再判断。
