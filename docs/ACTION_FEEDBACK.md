# Learn-X Action Feedback 周报

Action Feedback 是每周流程中的核心行动 / 反馈输入，独立于最终 Weekly Output。它只记录本周在当前季度「短期核心议题」下真实发生的行动和反馈；阶段 1 与周记草稿同时生成，用户默认与周记一起审核通过，需要时直接修改。阶段 2 的 Process Pack 自动嵌入完整快照供 AI Chat 阅读，最终 Weekly Output 据此综合判断，但不重复整张表。独立 `action-feedback.md` 保持可编辑，也是阶段 3 写入 Base 的依据；若在 Pack 生成后修改，再运行一次 `process:weekly` 更新快照。

## 产品边界

季度核心议题文档定义本周期的短期议题。每周报告固定展示这些议题，长期、中期议题不进入周报主表；没有新事项的议题保留为空，不自动新增人生议题。

用户可见格式只有三列：

```markdown
| 短期核心议题 | 行动 | 反馈 |
|---|---|---|
| 北大光华价值投资课 | [x] 上课 + 作业 | 已完成并待案例校准 |
| 和丽姐深度合作 | [x] 首次沟通合作形式与分工 | 已完成首次沟通 |
| 大理定居考察-12月 | — | 本周仅有 12 月旅行计划，未见实际考察或反馈 |
```

约束：

- 总可见字符数不超过 1000；
- `[ ]` / `[x]` 只表示尚未授权 / 已授权写入 Base，不表示报告审核状态或行动状态；
- `—` 表示核对本周可用来源后，没有实际行动或反馈；未来计划可以作为背景说明，但不能写成已发生行动。相关来源缺失时标为待核对，不能伪装成 `—`；
- 同一议题可以有多行，同周同议题同一行动的反馈合并为一行；
- 不展示状态、反馈类型、下一步、证据或时间字段。

## 数据模型

一条记录是一个行动反馈事件，而不是跨周任务：

```text
目标周 + 短期核心议题 + 行动 + 反馈 = 一条事件
```

同一行动隔几周再次发生时生成新的时间事件，不覆盖历史，也不要求 `continue/done/stopped`。Base 是后台事件存储，不是用户填写界面。

新事件字段：

| 字段 | 用途 |
|---|---|
| 短期核心议题 | 事件归属 |
| 行动 | 本次行动 |
| 反馈 | 本次反馈 |
| 周期时间 | 由目标周自动生成，记录事件归属周 |
| 事件创建时间 | Base 自动生成；旧字段 `创建时间` 保留兼容，作为年/月/周时间分组和组内排序基准 |
| 事件键 | 后台幂等去重，不展示 |

旧字段（如状态、反馈类型、下一步、来源证据、行动 ID）保留兼容历史数据，但新流程不依赖、不要求填写。时间分组使用既有 `base-time-group` Skill，不在报告中增加时间字段。

显式执行 `npm run action:feedback -- migrate` 时，还会确保后台公式字段 `年`、`月`、`年度第几周` 存在；它们只服务 Base 的时间回看，不进入用户周报。时间分组视图仍由 `base-time-group` Skill 单独配置，不由周同步自动改动。

## 流程

```text
同步核心议题镜像 + 采集本周输入
        ↓
阶段 1 生成周记草稿和 Action Feedback 初稿
        ↓
用户共同审核；“周记已确认”同时确认两份草稿
        ↓
阶段 2 一次生成 Process Pack，第 8 节嵌入完整报告快照
        ↓
最终 Weekly Output 消费内嵌快照中的有效行动反馈
        ↓
阶段 3 仅读取 action-feedback.md，写入 Base 事件表并读回校验
```

初稿保持当前议题原始顺序，模板初始行使用“待核对”占位；阶段 1 由 Codex 对照本周 `ready` 来源填候选，缺失来源不能推出“无事项”，只有核对后确认无行动 / 反馈才用 `—`。有证据且填写完整的行动候选默认 `[x]`，报告随周记共同审核通过，无需逐行勾选；用户发现问题时可删除或修改。若需保留某行供 Weekly Output 使用但不写入 Base，可改为 `[ ]`。用户填写后的报告不覆盖；只允许在确认周记比文件更新、且文件与已知空白模板完全一致时刷新旧模板。模板会在不可见的 HTML 注释中保存议题名称与 revision 快照；用户编辑时应保留该注释，以便后续即使季度文档更新，也能按报告生成时的议题基线校验。核心议题镜像缺失或状态不是 `fresh` 时标记 `needs_review`，不得生成伪造的空议题。线上核心议题更新后，先运行 `npm run sync:life-core` 再生成本地周报。

## 幂等与失败

后台事件键为：

```text
sha256(目标周 + 短期核心议题 + 规范化行动)
```

同周同议题同行动重复运行时更新同一事件；反馈变化更新反馈；不同周生成新事件。报告缺少任一基线议题、出现未在基线中的主题、超过 1000 字或缺少核心议题镜像时，停止 Base 写入并返回 `needs_review` / 失败原因。

每次 Base 写入后优先用返回的记录 ID 单条读回，并比较事件键及全部写入字段；只有写入响应没有记录 ID 时才按事件键定位。这样避免每条事件都扫描整张历史表。历史记录不批量迁移、不删除旧字段；已有旧 Base 需要新增字段时，显式执行 `npm run action:feedback -- migrate`，不在周流程中自动改结构。

## 与 Weekly Output、Memory 的边界

Action Feedback 是最终 Weekly Output 的一等现实输入，但不设置数字权重。Weekly Output 可在相关分析中综合随周记共同审核的有效行动反馈、调整主线判断；`[ ]` / `[x]` 仅决定是否写入 Base，不影响行内容是否用于周报。不固定对应某个输出项，也不得复制完整三列表格。Action Feedback 不自动升级为 Memory、道、法或术。
