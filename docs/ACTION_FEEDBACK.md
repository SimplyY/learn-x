# Learn-X Action Feedback 周报

Action Feedback 是每周流程中的中间产物，独立于最终 Weekly Output。它只记录本周在当前季度「短期核心议题」下真实发生的行动和反馈；最终 Weekly Output 读取它进行综合判断，但不重复整张表。

## 产品边界

季度核心议题文档定义本周期的短期议题。每周报告固定展示这些议题，长期、中期议题不进入周报主表；没有新事项的议题保留为空，不自动新增人生议题。

用户可见格式只有三列：

```markdown
| 短期核心议题 | 行动 | 反馈 |
|---|---|---|
| 北大光华价值投资课 | [ ] 上课 + 作业 | 待补充 |
| 和丽姐深度合作 | [x] 首次沟通合作形式与分工 | 已完成首次沟通 |
| 读书会 | — | 本周无新事项 |
```

约束：

- 总可见字符数不超过 1000；
- `[ ]` / `[x]` 只表示未确认 / 已确认写入 Base，不表示行动状态；
- `—` 表示本周没有相关事项；缺失来源不能伪装成 `—`；
- 同一议题可以有多行，同周同议题同一行动的反馈合并为一行；
- 不展示状态、反馈类型、下一步、证据或时间字段。

## 数据模型

一条记录是一个行动反馈事件，而不是跨周任务：

```text
目标周 + 短期核心议题 + 行动 + 反馈 = 一条事件
```

同一行动隔几周再次发生时生成新的时间事件，不覆盖历史，也不要求 `continue/done/stopped`。Base 是后台事件存储，不是用户填写界面。

新事件字段：

| 字段 | 用途 |
|---|---|
| 短期核心议题 | 事件归属 |
| 行动 | 本次行动 |
| 反馈 | 本次反馈 |
| 周期时间 | 由目标周自动生成，用于时间分组 |
| 事件创建时间 | Base 自动生成；旧字段 `创建时间` 保留兼容，不参与新事件时间分组 |
| 事件键 | 后台幂等去重，不展示 |

旧字段（如状态、反馈类型、下一步、来源证据、行动 ID）保留兼容历史数据，但新流程不依赖、不要求填写。时间分组使用既有 `base-time-group` Skill，不在报告中增加时间字段。

显式执行 `npm run action:feedback -- migrate` 时，还会确保后台公式字段 `年`、`月`、`年度第几周` 存在；它们只服务 Base 的时间回看，不进入用户周报。时间分组视图仍由 `base-time-group` Skill 单独配置，不由周同步自动改动。

## 流程

```text
同步核心议题镜像 + 采集本周输入
        ↓
生成 04_output/_dist/weekly/YYYY-Www/action-feedback.md 模板
        ↓
用户填写、修改并确认 [x]
        ↓
最终 Weekly Output 优先消费已确认行动反馈
        ↓
阶段 3 仅读取 action-feedback.md，写入 Base 事件表并读回校验
```

模板生成时保持当前议题原始顺序，已有报告不覆盖。核心议题镜像缺失或不可验证时标记 `needs_review`，不得生成伪造的空议题。线上核心议题更新后，先运行 `npm run sync:life-core` 再生成本地周报。

## 幂等与失败

后台事件键为：

```text
sha256(目标周 + 短期核心议题 + 规范化行动)
```

同周同议题同行动重复运行时更新同一事件；反馈变化更新反馈；不同周生成新事件。报告缺少任一基线议题、出现未在基线中的主题、超过 1000 字或缺少核心议题镜像时，停止 Base 写入并返回 `needs_review` / 失败原因。

每次 Base 写入后必须按事件键读回并比较字段。历史记录不批量迁移、不删除旧字段；已有旧 Base 需要新增字段时，显式执行 `npm run action:feedback -- migrate`，不在周流程中自动改结构。

## 与 Weekly Output、Memory 的边界

Action Feedback 是最终 Weekly Output 的一等现实输入，但不设置数字权重。Weekly Output 可以据已确认行动反馈重排本周主线、指出反馈如何改变判断，并在输出项 7 写简短摘要；不得复制完整三列表格。Action Feedback 不自动升级为 Memory、道、法或术。
